## 1. 프로젝트 개요

### 1.1 목적
Wanted.co.kr 웹사이트의 주요 기능에 대한 품질 검증 및 개선사항 도출

### 1.2 범위
**포함**:
- 검색 기능
- 필터링 기능
- 채용공고 조회
- UI/UX 검증
- 성능 분석

**제외**:
- 실제 지원 프로세스
- 로그인/회원가입 (테스트 계정 없음)
- 결제 기능
- 보안 취약점 테스트
- 대규모 부하 테스트

### 1.3 목표
- 30개 테스트 케이스 100% 실행
- 자동화율 50% 달성
- 버그 10건 이상 발견
- 실무 수준의 포트폴리오 완성

## 2. 사이트 기능 분석

### 2.1 주요 기능 구조
```
Wanted.co.kr
├── 메인 페이지 (/)
│   ├── 헤더
│   ├── 메인
│   └── 푸터
│
├── 채용 리스트 페이지 (/wdlist)
│   ├── 필터
│   ├── 태그
│   └── 채용 리스트
│
├── 채용 상세 페이지 (/wd/{id})
│   ├── 채용 공고 정보
│   ├── 회사 위치 정보
│   └── 지원하기
|
├── 검색 페이지 (/wd/{id})
│   ├── 채용 공고 정보
│   ├── 회사 위치 정보
│   └── 지원하기

```

### 2.2 URL 패턴
- 메인: `https://www.wanted.co.kr/`
- 검색: `https://www.wanted.co.kr/search?query={keyword}`
- 채용 리스트 : `https://www.wanted.co.kr/wdlist?query={keyword}`
- 채용 상세 페이지: `https://www.wanted.co.kr/wd/{job_id}`

## 4. 테스트 전략

### 4.1 자동화 vs 수동 비율
```
총 30개 케이스:
├── 자동화 (50%): 15개
│   ├── 검색 기능: 5개
│   ├── 필터 기능: 4개
│   ├── 네비게이션: 3개
│   └── 기본 동작: 3개
│
└── 수동 (50%): 15개
    ├── 반응형 UI: 3개
    ├── 시각적 검증: 5개
    ├── 탐색적 테스트: 4개
    └── UX 흐름: 3개
```

### 4.2 자동화 기준
**자동화 대상**:
- 반복적이고 안정적인 기능
- 명확한 검증 기준
- 회귀 테스트 필요
- 데이터 기반 검증

**수동 테스트 대상**:
- 시각적 검증 필요
- 사용자 경험 평가
- 탐색적 테스트
- 변경이 잦은 기능

### 4.3 우선순위

| 우선순위 | 영역 | 케이스 수 |
|---------|------|----------|
| **P0 (Critical)** | 검색, 필터 | 8개 |
| **P1 (High)** | 공고 상세, 정렬 | 14개 |
| **P2 (Medium)** | UI/UX, 네비게이션 | 8개 |
